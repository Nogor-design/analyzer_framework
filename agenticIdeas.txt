2) Reference architecture options (choose the level of control you want)
Option A — “Fast start”: Deep Agents harness + your domain tools
Use Deep Agents as the outer harness (planning + filesystem + subagents), and plug in your market-analysis tools. Deep Agents advertises built-ins like a planning todo tool, filesystem tools, optional shell execution, and a sub-agent delegation tool. [github.com], [deepwiki.com]

Pros: Quick to get an agent working; batteries included. [github.com], [deepwiki.com]
Cons: Slightly more opinionated; you’ll still want to wrap domain logic carefully.

Option B — “Maximum control”: Native LangGraph StateGraph with your tools
Build a custom StateGraph and nodes for each step of analysis, evaluation, reporting, and routing. LangGraph is positioned as low-level orchestration for long-running, stateful workflows with durable execution and memory. [github.com], [docs.langchain.com]

Pros: Best for complex branching, retries, human-in-loop checkpoints, and custom state. [docs.langchain.com], [deepwiki.com]
Cons: More wiring up front.

Option C — Hybrid (often best): Deep Agents for “agent loop”, LangGraph subgraphs for “pipelines”
Use Deep Agents for planning / context management / delegation, and implement your core market pipeline as a LangGraph subgraph (clean separation between “agentic decisions” and “deterministic computation”). This mirrors the “hybrid architecture pattern” separation you used in PROJECT_PLAN (decouple search/heuristics from evaluation/scoring). [onedrive.live.com], [github.com], [github.com]

7) Risk log (the big things that typically bite)


Tool calling fragility
Deep Agents requires a tool-calling-capable model. If your local model sometimes “refuses” to call tools or hallucinates arguments, you’ll need stricter schemas and guardrails. [docs.langchain.com]


Context bloat (slow + confused agent)
Deep Agents explicitly includes filesystem tools and auto-summarization/context management, which is a strong hint to offload bulky outputs to files. [github.com], [deepwiki.com]


Long-running workflow failures
LangGraph emphasizes durable execution and resumption for long-running stateful workflows—lean into that if your backtests take time. [docs.langchain.com]


Non-determinism in analysis decisions
Even if tools are deterministic, the agent’s routing may not be. Use evaluation nodes and explicit stop rules.(Recommendation.)
